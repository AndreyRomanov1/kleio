# Kleio

_Клио — муза истории._

Git для VS Code и VSCodium в духе JetBrains IDE: граф коммитов, из которого можно работать, один просмотрщик
diff для любого набора изменений, история и blame в один клик, interactive rebase и конфликты в нормальных
окнах, merge requests GitLab и ревью прямо в редакторе.

Сделан под работу, где код в основном пишут агенты и коллеги, а твоя задача — его читать: любое изменение
открывается во встроенном diff-редакторе с работающим языковым сервером, а файл справа можно сразу править.

## Возможности

**Лог и diff**

- **Граф коммитов** всех веток, remote и worktree; виртуальная прокрутка выдерживает десятки тысяч
  коммитов; фильтр по тексту, автору и хэшу, поиск набором с клавиатуры.
- **Панель веток**: HEAD, избранное, локальные и удалённые ветки деревом, теги, stash, счётчики ↑↓;
  **фокус** оставляет в логе только выбранные ветки.
- **Один просмотрщик diff для любого набора изменений** на встроенном diff-редакторе: `F7` / `Shift+F7`
  идут по изменениям и дальше в следующий файл, `F4` открывает файл для правки. Если ревизия совпадает с
  файлом на диске, справа открыт сам этот файл.
- **История и blame**: история файла или выделенных строк с diff рядом, аннотации blame со ссылками в лог,
  основной автор над объявлениями.

**Работа с историей**

- **Окно коммита**: изменения с галочками, **часть файла по кускам**, amend, недавние сообщения, откат
  файлов или кусков, stash. По умолчанию — как в Rider: отмеченные файлы и куски коммитятся в том виде,
  в каком они на диске, через временный индекс, а то, что ты застейджил сам, не трогается. С галкой
  **Stage** галочки показывают и меняют индекс git, а коммитится то, что в stage, как в `git commit`.

  ![Коммит части файла](docs/images/commit.png)

- **Ветки**: checkout (smart checkout через stash; замена локальной ветки, разошедшейся после rebase на
  сервере, с проверкой, что ничего не потеряется), checkout в новый worktree, merge, rebase, cherry-pick,
  revert, reset. Остановившаяся операция показывает полосу с «Продолжить / Пропустить / Прервать».
- **«Обновить проект»** скачивает всё из remote и подтягивает текущую ветку — merge или rebase, Kleio
  спросит в первый раз; другую ветку без своих коммитов можно обновить, не переключаясь на неё.
  Незакоммиченные изменения прячутся на время операции; если они вернулись с конфликтами, Kleio скажет
  об этом и откроет конфликты.
- **Диалог push**: исходящие коммиты всех веток с diff; разошедшаяся ветка отправляется только через
  force-with-lease по тому состоянию, что было в диалоге, и никогда — в защищённые ветки.

  ![Push](docs/images/push.png)

- **Interactive rebase**: pick, reword, edit, squash, fixup, drop; выдели несколько коммитов и объедини их
  в один; порядок — перетаскиванием или `Alt+↑/↓`; сообщения правятся прямо в окне. Git ни разу не
  открывает редактор.

  ![Interactive rebase](docs/images/rebase.png)

- **Конфликты**: список конфликтных файлов с настоящими именами сторон; взять одну сторону или слить во
  встроенном трёхпанельном merge editor. «Завершить слияние» отмечает файл разрешённым и предлагает
  продолжить операцию.

  ![Слияние](docs/images/merge.png)

**GitLab** (GitHub — пока только ссылки)

- Без токена: ссылки на коммиты, ветки и файлы, номера MR в логе, создание MR при push, ссылки на трекер
  задач из сообщений коммитов и имён веток.
- С API: статус MR и пайплайнов в логе, влитые MR по всей истории, карточка MR с джобами и дочерними
  пайплайнами, логи джоб в редакторе, перезапуск и ручные джобы, аппрув, вливание, rebase на сервере.
- **Ревью в просмотрщике diff**: треды прямо в коде, комментарии сразу или черновиками, resolve, переход
  по замечаниям. Каждый комментарий сначала пишется в локальный журнал, поэтому набранное не теряется.

## Установка

Скачай `kleio-<версия>.vsix` из [Releases](https://github.com/AndreyRomanov1/kleio/releases) и поставь:
`codium --install-extension kleio-<версия>.vsix` (или `code …`), либо Extensions → `…` → Install from
VSIX. Kleio работает только в доверенных локальных папках: git выполняет хуки и настройки репозитория.

Доступ к GitLab берётся из расширения [GitLab Workflow](https://open-vsx.org/extension/GitLab/gitlab-workflow),
если в нём выполнен вход, или из личного токена (команда «Подключить GitLab…», scope `api`) — он хранится в
защищённом хранилище редактора.

## Настройки

| Настройка                         | По умолчанию                          | Что делает                                                                               |
| --------------------------------- | ------------------------------------- | ---------------------------------------------------------------------------------------- |
| `kleio.autolinks`                 | `[]`                                  | Правила ссылок из текста: `{"pattern": "\\bPROJ-\\d+\\b", "url": "https://tracker/$0"}`  |
| `kleio.hosting.instances`         | `{}`                                  | Тип хостинга для своих серверов, например `{"git.example.com": "gitlab"}`                |
| `kleio.update.method`             | `ask`                                 | Как «Обновить проект» подтягивает ветку со своими коммитами: `merge` или `rebase`        |
| `kleio.commit.stagingArea`        | `false`                               | Окно коммита работает с индексом git (галка **Stage**)                                   |
| `kleio.hosting.backgroundRefresh` | `true`                                | Раз в несколько минут спрашивать у сервера ссылки на MR; выключи, если SSH просит пароль |
| `kleio.push.protectedBranches`    | `["master", "main"]`                  | Ветки, куда никогда не идёт force push; работает `*`, например `release/*`               |
| `kleio.worktree.path`             | `${repoParent}/${repoName}-${branch}` | Папка нового worktree                                                                    |
| `kleio.worktree.copyFiles`        | `[]`                                  | Неотслеживаемые файлы, которые копируются в новый worktree, например локальные секреты   |
| `kleio.codeLens.authors`          | `true`                                | Основной автор и число остальных над классами и методами                                 |
| `kleio.history.showDiffOnSelect`  | `true`                                | Во вкладке истории сразу показывать diff выбранного коммита                              |

## Клавиши

`F7` / `Shift+F7` в diff Kleio идут по изменениям и переходят в следующий файл. Расширения с раскладками
(например, IntelliJ IDEA Keybindings) вешают те же клавиши на diff-редактор, и между двумя расширениями VS
Code выбирает непредсказуемо. Пользовательские привязки всегда главнее — если F7 не уходит дальше файла,
добавь в `keybindings.json`:

```json
[
  {
    "key": "f7",
    "command": "kleio.diff.nextChange",
    "when": "kleio.inChangeSet && textCompareEditorVisible"
  },
  {
    "key": "shift+f7",
    "command": "kleio.diff.previousChange",
    "when": "kleio.inChangeSet && textCompareEditorVisible"
  }
]
```

В merge editor `Ctrl+Enter` завершает слияние и отмечает файл разрешённым.

## Разработка

Нужны Node.js 20+ и git.

```sh
npm install
npm run build              # расширение и webview в dist/
npm run watch              # пересборка на лету; F5 в VS Code запускает Extension Development Host
npm test                   # юнит-тесты на настоящих git-репозиториях во временной папке
npm run test:integration   # тесты внутри настоящего редактора; KLEIO_CODE=/путь/к/codium
npm run preview -- <репо>  # интерфейс в браузере на настоящем репозитории; ничего не коммитит и не пушит
npm run package            # kleio.vsix
```

На Linux интеграционные тесты запускают редактор под `xvfb-run` в одноразовом профиле.
